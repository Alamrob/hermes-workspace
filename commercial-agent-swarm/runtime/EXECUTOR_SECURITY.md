# Hermes executor security boundary

The broker and Hermes executor are separate trust zones. Broker composition may own the PostgreSQL, approval, mail and webhook capabilities, but depends only on the Unix-socket `ExecutorPort`; it must not instantiate `HermesExecutor` or receive `CUSTOM_API_KEY`/`CUSTOM_API_KEY_FILE`. Executor composition owns the root-only `CUSTOM_API_KEY_FILE` and immutable profile seed, but must not receive database, mail, Telegram, Docker, SSH or host credentials. The fixed socket is a uint32be-length-prefixed, closed JSON protocol (1 MiB maximum), one request per half-closed connection, with a single executor request in flight.

The trusted executor supervisor runs as effective UID/GID `10000:10000`; Hermes runs as the distinct UID/GID `10002:10002`. A fixed, no-shell `/usr/bin/setpriv` bootstrap immediately replaces root PID 1 with the supervisor, limits every capability set to exactly `CHOWN`, `SETUID`, `SETGID`, and `SETPCAP` (`0x1c1`), clears supplementary groups, and sets `no_new_privs`. Startup rejects PID other than 1, UID/GID other than 10000, any extra/missing capability, supplementary group, or missing `no_new_privs`. `SETPCAP` is the reviewed exception required to clear the child's capability bounding set; it is not retained by Hermes.

The supervisor copies the immutable `10000:10000`, non-writable seed into direct children of the validated temporary root, rejects symlinks/special files/hard-linked files, and recursively changes only those new trees to `10002:10002`. Cleanup reclaims directories without following child-created symlinks, so `CAP_DAC_OVERRIDE` and host-root access are not needed. The child launcher is fixed `/usr/bin/setpriv --clear-groups --reuid=10002 --regid=10002 --inh-caps=-all --ambient-caps=-all --bounding-set=-all --no-new-privs -- <fixed Hermes argv>` with `shell:false`. Linux gates require groups `[10002]`, all child capability sets zero, and `NoNewPrivs: 1`.

The custom API key and broker secrets are Docker secret files with the exact contract `root:10000 0440`: regular, single-link files, no other bits, no symlinks, bounded to 16 KiB. Readers open with `O_NOFOLLOW`, validate the opened descriptor, and require the process to be a member of GID `10000`. The child receives exactly `HERMES_HOME`, `HOME`, `LANG`, fixed `PATH`, and the single in-memory `CUSTOM_API_KEY`; it never receives the key-file path. Each assignment gets unique home and empty working directories, both recursively removed after success, malformed output, process error or timeout.

The fixed IPC directory is `10000:11000 02770`; the supervisor is not a member of GID 11000 and relies on setgid inheritance for the `0660` socket. Hermes is neither owner nor group member and cannot connect to or unlink it. The supervisor secret remains `root:10000 0440`; Hermes receives only the in-memory key environment value and cannot read the file.

The executor container must run with a minimal init/subreaper enabled. On timeout or output overflow, the runner sends `SIGKILL` to the detached process group and does not return until that group no longer exists; it fails closed with `HERMES_PROCESS_GROUP_NOT_REAPED` if the init contract is absent or broken.

The adapter invokes only `/opt/hermes/.venv/bin/hermes -p <closed-profile> -z <prompt> --usage-file <controlled-path>`, with `shell: false`, fixed `PATH=/opt/hermes/.venv/bin:/usr/local/bin:/usr/bin:/bin`, and an explicitly empty controlled CWD. This exact `-z` prompt path was verified against the pinned Hermes 0.20.1 image; unsupported `-q`/`--cli chat` variants are not introduced. Prompts are single argv data values with separate trusted context and `untrusted_data`; deployment must not add `--yolo`, `--accept-hooks`, delegation, profile/model/provider/tool overrides, inherited environment variables or concurrent execution. Exit code and stdout are insufficient: success requires the canonical AgentResult plus trusted Hermes usage, expected model/provider and broker-side pricing from the versioned official OpenCode Go snapshot. Preflight rejects an expired snapshot, unpublished cache-write rate or reservation below worst-case output-token usage before the key is read or a process starts. Provider usage value and incremental cash cost are stored separately; the included Go quota is never mislabeled as a cash charge.

The `opencode-go-2026-08-21-v2` snapshot uses the published DeepSeek V4 Flash peak/off-peak input, output and cached-read rates. The official Cached Write column is `-`: preflight therefore reserves against the higher peak output rate and does not invent a cached-write price. If runtime telemetry nevertheless reports any cached-write token, post-execution reconciliation fails closed and the authoritative Usage reservation remains held until reviewed.

Production also requires every approved profile manifest to fix `model.max_tokens` and `agent.max_turns`; the broker reservation must cover their worst-case token and API-call ceilings. Existing profiles that omit those bounds deliberately fail executor preflight and are not deployable through this adapter.
