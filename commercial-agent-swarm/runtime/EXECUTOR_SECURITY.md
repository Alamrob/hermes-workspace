# Hermes executor security boundary

The broker and Hermes executor are separate trust zones. Broker composition may own the PostgreSQL, approval, mail and webhook capabilities, but depends only on the Unix-socket `ExecutorPort`; it must not instantiate `HermesExecutor` or receive `CUSTOM_API_KEY`/`CUSTOM_API_KEY_FILE`. Executor composition owns the root-only `CUSTOM_API_KEY_FILE` and immutable profile seed, but must not receive database, mail, Telegram, Docker, SSH or host credentials. The fixed socket is a uint32be-length-prefixed, closed JSON protocol (1 MiB maximum), one request per half-closed connection, with a single executor request in flight.

The executor launcher runs as a dedicated root-owned adapter only long enough to verify and copy a root-owned, non-writable, symlink-free seed, transfer the ephemeral copy to UID/GID `10000`, and spawn that identity. Startup rejects an executor primary or supplementary membership in the IPC GID, and the Linux identity test demonstrates that the child cannot traverse the root:IPC-group socket directory or read the root-only key. Its Linux capability bounding set should contain only `CAP_CHOWN`, `CAP_SETUID`, `CAP_SETGID` and `CAP_DAC_OVERRIDE`; the last capability is retained only so the adapter can remove the child-owned `0700` home, and the set is cleared after cleanup. It does not need `CAP_SYS_ADMIN`, `CAP_NET_ADMIN`, Docker socket access or host mounts. The child receives exactly `HERMES_HOME`, `HOME`, `LANG`, fixed `PATH`, and the single in-memory `CUSTOM_API_KEY`; it never receives the key-file path. The fixed temporary root must be pre-created securely. Each assignment gets unique home and empty working directories, both recursively removed after success, malformed output, process error or timeout.

The executor container must run with a minimal init/subreaper enabled. On timeout or output overflow, the runner sends `SIGKILL` to the detached process group and does not return until that group no longer exists; it fails closed with `HERMES_PROCESS_GROUP_NOT_REAPED` if the init contract is absent or broken.

The adapter invokes only `/opt/hermes/.venv/bin/hermes -p <closed-profile> -z <prompt> --usage-file <controlled-path>`, with `shell: false`, fixed `PATH=/opt/hermes/.venv/bin:/usr/local/bin:/usr/bin:/bin`, and an explicitly empty controlled CWD. This exact `-z` prompt path was verified against the pinned Hermes 0.20.1 image; unsupported `-q`/`--cli chat` variants are not introduced. Prompts are single argv data values with separate trusted context and `untrusted_data`; deployment must not add `--yolo`, `--accept-hooks`, delegation, profile/model/provider/tool overrides, inherited environment variables or concurrent execution. Exit code and stdout are insufficient: success requires the canonical AgentResult plus trusted Hermes usage, expected model/provider and broker-side pricing from the versioned official OpenCode Go snapshot. Preflight rejects an expired snapshot, unpublished cache-write rate or reservation below worst-case output-token usage before the key is read or a process starts. Provider usage value and incremental cash cost are stored separately; the included Go quota is never mislabeled as a cash charge.

Production also requires every approved profile manifest to fix `model.max_tokens` and `agent.max_turns`; the broker reservation must cover their worst-case token and API-call ceilings. Existing profiles that omit those bounds deliberately fail executor preflight and are not deployable through this adapter.
